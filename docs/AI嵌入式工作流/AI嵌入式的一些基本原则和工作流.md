# AI 嵌入式开发基本原则与工作流

> 本文档规定了使用 AI 辅助编写嵌入式代码时应遵循的原则、规范和最佳实践，以确保代码的可维护性、可扩展性和性能。

---

## 一、AI 嵌入式代码常见问题

在使用 AI 辅助编写嵌入式代码时，经常遇到以下问题：

### 1.1 缺乏系统架构意识

- AI 往往只关注当前功能的实现，忽视代码的长期维护和可扩展性
- 缺乏模块化思维，代码耦合度过高

### 1.2 资源使用不当

- **滥用阻塞等待**：频繁使用 `while` 循环等待，占用 CPU 资源，影响系统实时性
- **内存使用不合理**：喜欢创建大量分散变量，而不是使用结构体进行组织
- **忽视中断上下文**：在中断中执行耗时操作

### 1.3 代码风格不统一

- 即使提供了风格文档，AI 也难以保持一致性
- 命名规范、缩进、注释风格时好时坏

### 1.4 缺乏复用思想

- 重复代码片段大量出现，宁愿复制粘贴也不愿封装函数
- 相同逻辑散落在多处，难以维护

### 1.5 变量管理混乱

- 倾向于创建多个独立变量，而非将相关变量组织到结构体中
- 全局变量滥用，缺乏封装

### 1.6 冗余代码

- 生成未使用的变量、函数或注释
- 代码过于冗长，不够简洁

---

## 二、核心解决方案

针对上述问题，制定以下强制性规范：

### 2.1 架构设计原则

- **模块化设计**：每个功能独立成模块，通过接口交互
- **分层架构**：应用层 → 模块层 → BSP 层 → HAL 层
- **单一职责**：每个函数只完成一个明确任务

### 2.2 资源管理规范

- **严禁阻塞**：禁止使用 `while` 循环等待，必须使用**状态机 + 定时器中断**模式
- **延时机制**：使用 `count--` 递减计数器实现非阻塞延时
- **内存优化**：相关变量必须封装在结构体内，避免散乱全局变量

### 2.3 代码风格统一

- 提供完整的范例文件作为模板
- 所有代码必须参照范例的风格和结构
- 使用中文注释，保持清晰的逻辑说明

## 三、标准模块范例

以下是一个完整的标准功能模块范例，展示了正确的代码组织方式：

### 3.1 头文件 (function.h)

```c
#ifndef _FUNCTION_H_
#define _FUNCTION_H_

#include "RM_typedef.h"

/* 状态枚举定义 */
typedef enum __Function_State_Enum
{
    FUNC_IDLE,   // 空闲状态
    FUNC_BUSY,   // 忙碌状态
    FUNC_ERROR   // 错误状态
} Function_State_Enum;

/* 模块数据结构体 - 所有变量封装在此 */
typedef struct __Function_Struct
{
    uint8_t  state;  // 当前状态
    uint16_t count;  // 计时计数器（单位：ms）
    uint8_t  data;   // 数据字段
} Function_Struct;

/* 对外接口声明 */
extern Function_Struct Function;

void Function_Init(void);
void Function_Task(void);
void Function_Timing_Handle(void);

#endif /* _FUNCTION_H_ */
```

### 3.2 源文件 (function.c)

```c
#include "Function.h"

/* 模块实例定义 */
Function_Struct Function;

/**
 * @brief  模块初始化
 * @note   在系统启动时调用，初始化状态和变量
 */
void Function_Init(void)
{
    Function.state = FUNC_IDLE;
    Function.count = 0;
    Function.data  = 0;
}

/**
 * @brief  模块主任务函数
 * @note   在主循环中周期性调用，使用状态机实现非阻塞处理
 *         通过 count 控制执行频率，严禁使用 while 等待
 */
void Function_Task(void)
{
    /* 时间片控制：count > 0 时跳过本次执行 */
    if (Function.count > 0)
    {
        return;
    }

    switch (Function.state)
    {
        case FUNC_IDLE:
            Function.count = 100;  // 设置 100ms 执行周期
            /* 空闲状态处理逻辑 */
            break;

        case FUNC_BUSY:
            Function.count = 100;  // 设置 100ms 执行周期
            /* 忙碌状态处理逻辑 */
            break;

        case FUNC_ERROR:
            Function.count = 100;  // 设置 100ms 执行周期
            /* 错误状态处理逻辑 */
            break;

        default:
            Function.state = FUNC_IDLE;  // 异常状态恢复
            break;
    }
}

/**
 * @brief  定时器中断处理函数
 * @note   必须放入 1ms 定时器中断中，递减计数器实现非阻塞延时
 *         保持极简，仅做计数器递减，不执行复杂逻辑
 */
void Function_Timing_Handle(void)
{
    if (Function.count > 0)
    {
        Function.count--;
    }
}
```

## 四、关键规范详解

### 4.1 状态机设计模式

每个功能模块必须采用状态机设计：

1. **状态定义**：使用 `enum` 明确定义所有状态
2. **状态变量**：在结构体中使用 `state` 字段存储当前状态
3. **状态转换**：在 `Task` 函数中通过 `switch-case` 实现状态切换
4. **避免阻塞**：状态体内严禁使用 `while`、`delay` 等阻塞操作

### 4.2 非阻塞延时机制

这是嵌入式系统的核心机制：

```text
┌─────────────────────────────────────────────────────────┐
│                      主循环 (while(1))                   │
│  ┌─────────────────────────────────────────────────┐    │
│  │           Function_Task()                       │    │
│  │  if (count > 0) return;  ← 时间未到直接返回      │    │
│  │  switch(state) { 执行业务逻辑 }                  │    │
│  │  count = 100;  ← 重置计数器，设置下次执行时间    │    │
│  └─────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│              TIM3 定时器中断 (1ms)                       │
│  ┌─────────────────────────────────────────────────┐    │
│  │        Function_Timing_Handle()                 │    │
│  │  if (count > 0) count--;  ← 仅递减计数器        │    │
│  └─────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────┘
```

### 4.3 结构体封装要求

**正确做法**：

```c
typedef struct __Module_Struct
{
    uint8_t  state;      // 状态
    uint16_t count;      // 计时
    uint8_t  buffer[8];  // 数据缓冲
    void (*callback)(void);  // 回调函数
} Module_Struct;
```

**错误做法**：

```c
uint8_t  Module_state;       // ❌ 散乱变量
uint16_t Module_count;       // ❌ 难以管理
uint8_t  Module_buffer[8];   // ❌ 缺乏封装
```

### 4.4 定时器中断注册

当创建新模块时，需在 `bsp_tim_isr.c` 中注册定时器回调：

```c
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM3)
    {
        // 已有模块的回调
        Vofa_Callback();
        Robstride_Callback();
        Key_Callback();

        // 新增模块的回调 - 在此处添加
        Function_Timing_Handle();
    }
}
```

## 五、AI 提示词模板

向 AI 请求代码时，应包含以下关键提示词：

### 5.1 基础提示词（必须）

```text
请按照以下规范编写嵌入式 C 代码：

1. 【架构规范】
   - 使用模块化设计，功能独立封装
   - 所有变量必须封装在结构体内，禁止散乱全局变量
   - 提供 Init、Task、Timing_Handle 三个标准接口

2. 【状态机规范】
   - 使用 enum 定义状态：IDLE、BUSY、ERROR 等
   - 使用 switch-case 实现状态机
   - 严禁使用 while 循环等待或阻塞

3. 【时序规范】
   - 使用 count 计数器实现非阻塞延时
   - Task 函数开始时检查 count，大于 0 直接返回
   - Timing_Handle 函数放入 1ms 定时器中断，仅递减 count

4. 【代码风格】
   - 参照 function.c / function.h 范例文件
   - 使用中文注释说明关键逻辑
   - 函数和变量命名使用下划线命名法

5. 【优化要求】
   - 避免冗余代码，删除未使用的变量和函数
   - 提取重复逻辑为独立函数，提高复用性
   - 代码简洁，避免过度设计
```

### 5.2 高级提示词（可选）

```text
6. 【扩展性要求】
   - 预留配置参数接口，便于后续调整
   - 关键数值使用宏定义，便于修改
   - 考虑边界情况和错误处理

7. 【性能要求】
   - 中断函数保持极简，不执行耗时操作
   - 避免在中断中使用浮点运算
   - 合理控制 Task 函数执行周期，不过于频繁
```

## 七、最佳实践总结

| 场景         | 正确做法                      | 错误做法                  |
| ------------ | ----------------------------- | ------------------------- |
| 延时等待     | 使用 `count--` + 定时器中断   | `while(delay--);` 阻塞    |
| 状态管理     | `enum` + `switch-case` 状态机 | 使用多个 `bool` 标志位    |
| 变量组织     | 封装在结构体内                | 散乱的全局变量            |
| 周期执行     | Task 函数 + 时间片控制        | 在主循环中无脑循环        |
| 中断处理     | 仅做标记，主循环处理          | 在中断中执行业务逻辑      |
| 重复代码     | 封装为函数复用                | 复制粘贴多份              |
