**移植时需要遵守的时序约定**（写在 `lic411_port.h` 头部注释里）：

```
CLOCK  ‾‾|_|‾|_|‾|_|‾ ... ‾‾‾‾‾‾
DATA   ‾‾[ 命令 8 位 ]‾‾[ 编码器回应 ]
DE     ‾‾‾‾‾‾‾‾‾‾‾‾‾\____________
       └─ de_clocks ─┘
```

1. DE 拉高接管总线，DATA 先保持低 ≥2 µs（t_ST）
2. 连续打 `tx_len*8` 个时钟（LSB 先行），命令期结束时释放 DE
3. 继续打时钟并采样 DATA，收满 `rx_len` 字节
4. 时钟结束时保持高电平

关键参数：1.3125 MHz、SPI 模式 3（CPOL=1/CPHA=1）、命令 8 个时钟、帧 43 位

## 2. 通信时序

### 2.1 一次事务

```
时间 →
0 µs      2 µs         8 µs                              66 µs
│          │            │                                 │
│   t_ST   │  命令期    │           数据期                │
│          │  8 个时钟  │          56 个时钟              │
DE ‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾\_________________________
DATA  [低] [0,0 | 1,1,1,0,0,0]  [S E1 E2 + 35 位 + CRC5]
CLOCK ______|‾|_|‾|_|‾|_|‾ ... 64 个连续脉冲，1.3125 MHz
```

| 参数 | 值 | 说明 |
|---|---|---|
| 时钟频率 | 1.3125 MHz | 84 MHz / 64 |
| 一次时钟数 | 64 | 8 字节 |
| t_ST | ≥ 2 µs | 规范 2.3.1：首时钟前 DATA 保持低 |
| 命令期 | 8 个时钟（≈6.1 µs） | DE 保持高 |
| 事务周期 | 10 ms | `LIC411_PERIOD_MS` |
| SPI 模式 | 2（CPOL=1, CPHA=1Edge） | 下降沿采样 |

### 2.2 模式指令

规范第 14 页：

| M2 M1 M0 (M2)(M1)(M0) | 指令 |
|---|---|
| 0 0 0 1 1 1 | EnDat 2.1：不带附加信息 |
| **1 1 1 0 0 0** | **EnDat 2.2：带附加信息** |

线上字节（SPI 为 **LSB 先行**）：

```
0x1C = 0001 1100
线上顺序：0,0,1,1,1,0,0,0
          └┬┘ └──┬──┘
          2T   111000  ← EnDat 2.2
```

> ⚠️ **若把 SPI 改成 MSB 先行，字节值必须改成 `0x38`**，否则指令会变成 2.1。
> 误用 `0xE0`（线上 000111 = 2.1）会让编码器进入**连续时钟模式**，帧周期变为 51 个时钟。

### 2.3 收发流程

```
App_Encoder_Task()                每 1 ms 调用
  └─ Lic411_Task()                状态机
      ├─ IDLE  周期到 → Bsp_Endat_Start()
      │                   ├ ① DE 拉高（MOSI 已是低电平）
      │                   ├ ② 延时 2 µs（t_ST）
      │                   ├ ③ HAL_SPI_TransmitReceive_DMA（8 字节）
      │                   ├ ④ 延时 6 µs（命令期）
      │                   └ ⑤ DE 拉低（时钟继续跑完）
      ├─ WAIT  轮询 BSP 状态
      │        ├ DONE  → Lic411_Handle_Frame()
      │        ├ ERROR → 计数
      │        └ 超时 20 ms → Abort
      └─ 回调 HAL_SPI_TxRxCpltCallback()
                └ 丢弃第 1 字节，拷贝 7 字节给上层，state = DONE
```

## 3. 帧结构

### 3.1 实测帧格式（43 位）

```
位序号（RAW 内，0 起）:
  7        8      9      10 ... 44        45 ... 49
  S      Error1  Error2  位置值 35 位      CRC5
  ↑                                    ↑
 起始位(恒 1)                     MSB 位序
                         LSB 先行
```

| 字段 | 位数 | 说明 |
|---|---|---|
| S（起始位/报警位） | 1 | 恒为 1 |
| Error1 | 1 | 位置值无效（光源、污染、信号幅值） |
| Error2 | 1 | 供电电压超差 |
| 位置值 | **35** | LSB 先行 |
| CRC5 | 5 | MSB 位序 |

> **注意**：产品目录写"数据字位宽 36 位"，但**实测 35 位**才能让 CRC 通过。
> 规范 2.3.4 明确说：位宽是编码器里的参数（Word 13），必须从编码器读取。

### 3.2 错误位语义（规范 2.2）

- **Error1** = 位置值无效
- **Error2** = 供电电压超差
- **两者相互独立**，正常时**都为 0**

> ⚠️ 早期错误假设：认为 F1 与 F2 必须互反（EnDat 2.1 的约定）。
> 这导致健康帧（F1=F2=0）被全部拒绝，成功率只有 12%。

## 4. CRC 算法

### 4.1 规范定义（附录 A4）

- 5 位 CRC，多项式 `x^5 + x^3 + x + 1`
- 5 个触发器，**初值全 1**
- 数据按 **MSB 在前** 移入（实现上等价于：载荷按 LSB 先行顺序送入 LFSR）
- 输出时从 `ff[4]` 到 `ff[0]`，**每位取反**
- **报警位（起始位）也参与 CRC**（规范 A4 原文："The alarm bit is included in the formation of the CRC codes"）

### 4.2 实现

```c
/* 载荷 = [S, Error1, Error2, data(35 位, LSB 先行)] */
uint8_t Lic411_Crc5(const uint8_t *payload, uint16_t len)
{
    uint8_t ff[5] = {1, 1, 1, 1, 1};
    uint8_t ex, crc = 0;

    for (i = 0; i < len; i++)
    {
        ex = ff[4] ^ payload[i];
        ff[4] = ff[3];
        ff[3] = ff[2] ^ ex;
        ff[2] = ff[1];
        ff[1] = ff[0] ^ ex;
        ff[0] = ex;
    }

    /* 关键：输出顺序必须是 ff[4] -> ff[0] */
    for (i = 4; i >= 0; i--)
    {
        ff[i] = ff[i] ? 0 : 1;
        crc = (crc << 1) | ff[i];
    }
    return crc;
}
```

### 4.3 验证（规范自带的标准答案）

规范附录 A4.2 给了两个测试向量：

| 函数 | 输入 | 规范答案 | 我们的实现 |
|---|---|---|---|
| `MakeCrcNorm` | param8=13, param16=32793 | 14 | **14 ✅** |
| `MakeCrcPos` | clocks=25, e1=0, e2=1, highpos=0, lowpos=104462 | 3 | **3 ✅** |

> **踩过的坑**：厂商 demo 的 CRC 输出顺序是 `ff[0] → ff[4]`，和规范相反。
> 这导致长期无法解出任何帧。用规范标准答案反推才发现。

## 5. 解码流程

```
① 字节 → 位数组（LSB 先行）
② 找起始位：从 offset=7 开始，向两侧 ±2 试探（就近优先）
   条件：bits[offset] == 1
③ 错误位检查：E1 != 0 或 E2 != 0 → 丢弃
④ 取 35 位数据（LSB 先行）→ counts
⑤ CRC 校验（见第 4 节）→ 不等则丢弃
⑥ 连续性校验：|counts - last| > 1 mm → 丢弃
⑦ 三点中值滤波：取最近 3 帧中位数
⑧ 发布：mm = counts × LIC411_STEP_NM / 1e6
```

**为什么要 ±2 搜索**：`t_cal` 是**时间量**（≤5 µs），不是时钟数，
所以帧头相对时钟的偏移会逐次漂移 ±1 个时钟。

**为什么要中值滤波**：5 位 CRC 的假通过率约 1/32，
错位时可能解出合理但错误的值（实测偏差 80 µm）。

## 6. 踩过的七个坑

| # | 问题 | 现象 | 原因 | 修法 |
|---|---|---|---|---|
| 1 | 时钟中断 | 数据始终无法通过 CRC | "发 8 字节 + 收 8 字节"两次 DMA 之间有 4.9 µs 间隙 | 改为**一次 17 字节连续 DMA** |
| 2 | 模式指令错误 | 帧周期 51 个时钟、连续模式、f1=1 | 用了 `0xE0`（EnDat **2.1**） | 改 `0x1C`（2.2），编码器转为单帧、f1=0 |
| 3 | 数据位宽错误 | 36 位永远解不出 | 手册写 36，实际 **35**；扫描时步长 2 跳过了 35 | 改为 35 |
| 4 | CRC 位序错误 | 任何偏移都不过 | 输出顺序 `ff[0]→ff[4]`（厂商 demo 的写法） | 改为规范 `ff[4]→ff[0]` |
| 5 | CRC 覆盖范围错误 | 全部不过 | 漏了**起始位**（规范 A4："报警位参与 CRC"） | 载荷加入 S |
| 6 | F1/F2 互反假设 | 成功率仅 12% | 2.2 的错误位**相互独立**，健康时都是 0 | 删除互反检查，改为"任一为 1 则丢弃" |
| 7 | 接线接触不良 | RAW 全 FF，误判编码器损坏 | 端子松动（过压事件后） | 重新压接，恢复正常 |

## 10. 参数读取尝试记录（2026-11-18 补充）

### 10.1 已确认的事实

| 项目 | 结论 | 依据 |
|---|---|---|
| **测量步距** | **1 nm** | 规范「编码器概要」表：LIC 4100 → 1 nm |
| **与参考点无关** | 绝对式编码器 RM 位恒为高 | 规范原文 |
| **位宽 35 位** | 可信 | CRC 逐帧通过（位宽错则必失败） |
| **80 µm = 80,000 计数** | 物理事实 | 步距 1 nm × 80,000 |

### 10.2 关键指令字节（全部经实测/规范核对）

| 用途 | 模式位 | 线上字节 | 说明 |
|---|---|---|---|
| 发送位置值（带附加信息） | `111 000` | **0x1C** | 本项目主用 |
| 存储区的选择（2.1） | `001 110` | **0x70** | 读参数前必须发 |
| 选择附加数据（2.2） | `001 001` | **0x90** | 让位置帧带附加数据 |
| 编码器发送参数（2.1） | `100 011` | **0xC4** | 后跟地址 + 16 位哑元 |
| 编码器接收复位（2.1） | `101 010` | **0x54** | 上电流程第 1 步 |

> ⚠️ **踩过的坑**：`0x70` 与 `0x90` 极易混淆。
> 用 `0x70` 选存储区后再读位置，**附加数据不会出现**（这是正常的）；
> 只有 `0x90` 才选附加数据。

### 10.3 参数读取的实测结果

按规范流程执行：

```
① 上电等 1.5 s（t_SOT = 1.3 s）
② 发 0x54 复位，等 50 ms
③ 发 0x70 + MRS 码（选存储区）
④ 发 0xC4 + 地址 + 16 位哑元
⑤ 等 t_ac ≤ 12 ms
⑥ 收回应
```

**结果**：

| MRS | 回应 |
|---|---|
| 0xA1 / 0xA3 / 0xA7 | 全 `FF`（无响应） |
| **0xA5 / 0xBD** | **有回应，且随字地址变化** ✅ |

对 MRS 0xA5 的回应做 CRC 分析：

```
addr 0x0D → 52 FE FF 3F ...
addr 0x1C → 72 FC FF 3F FC ...
```

- **CRC 校验通过**（44 位载荷，起点位偏移 2）
- **地址 0x1C 的回显完全吻合**
- **但 16 位数据字段 = 0xFFFF（所有地址都一样）= "无数据"**

**结论**：地址被接受，但参数值未返回。

### 10.4 剩余的工作（未完成）

规范图 10 显示 EnDat 2.2 的参数访问是**多周期附加数据协议**：

| 顺序 | 数据通信 |
|---|---|
| 选存储区 | 位置值 + 选择 MRS 码 |
| 确认 MRS 码 | 位置值 + 确认 MRS 码 |
| 读取地址传输 | 位置值 + 选择需读取的地址 |
| **忙 bit = 0 的周期请求**（≤12 ms） | 位置值 + 任何附加数据 |
| **读取 LSB** | 位置值 + 附加数据 + 数据内容 |
| **读取 MSB** | 位置值 + 附加数据 + 数据内容 |

**每个周期都要解析 30 位附加数据块**（`[0][WRN][RM][Busy][8位地址/数据][8位数据][CRC5]`）。

实测发现：
- 重复发 `0xC4 + 地址` 10 次，回应**完全相同**（状态不推进）
- 选 MRS（`0x70` 或 `0x90`）后，位置帧尾部**始终是全 FF**（附加数据从未出现）

**这部分需要完整的《EnDat 2.2 应用说明》才能实现。**
